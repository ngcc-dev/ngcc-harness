## Attacks considered

- hash-34-1: A four-block reset prefix gives second preimages below the required levels (Design, Probable)

## Remediation

- **hash-34-1.** Root cause: every compression call is the same function of chaining value and block, the padding is 10* with no length field, the checksum is an XOR, and both initial values are zero. The palindrome `X‖Y‖Y‖X` with `P_X(0) = P_Y^{-1}(0)` therefore returns both feedback registers and the checksum to their initial values, and it can stand before any message. The costed repair is a block counter: the index of the block enters each compression call, including the final call on Σ. This is a standard technique (the block counter of HAIFA, Biham and Dunkelman, ePrint 2007/278) and the usual repair for a missing block counter; `report.md` records no proposed fix. The finding relies on the two calls on `Y`, and the two on `X`, being the same function, and on the blocks of `M` being compressed alike with and without the prefix; with an index in the call, the calls differ by position. Scope: Function, specification and code: lines 5 and 7 of Algorithm 1 and the input of Algorithm 2; in the code, the two absorb routines and the final call. Impact: none. An index XORed into one lane costs one XOR and one increment per call, against about 3,051 (Version I) and 8,154 (Version II) 64-bit operations in the call: +0.07% and +0.02% (count). A one-block message makes two calls, so the ratio for a short message is the same. The block length µ, the state length b, the round counts and the number of calls per message are unchanged. If the index were instead carried in 64 bits of each message block, the work per byte would rise by 1152/1088 = +5.9% at Version I and 2304/2240 = +2.9% at Version II (count), still under 10%. A length field in the padding (Merkle–Damgård strengthening) costs the same or less, since it adds a compression call only at particular lengths; it leaves the state reset in place and only stops the prefix from giving an equal digest, so it is not the repair relied on. The 2^(b/2) search of the finding yields second preimages only through the reset identity, so the costed repair changes the mode and not the state length; widening `b` until 2^(b/2) reaches 2^h would need a wider permutation and is not costed. Not checked: whether either change meets the required second-preimage levels; the reporter's posts and draft were not re-read; no repaired mode was written or run.
