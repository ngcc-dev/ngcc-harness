# Constant-time review: BIKE-MLThre

The sparse parity-check vectors and fallback `sigma` in `sk`, decoded error `e`, recovered message `m`, and shared secret are secret. The ciphertext and fixed parameter lengths are public. This follows the submitted `Implementations/reference` path only; optimized code and emitted assembly remain unreviewed.

`kem.c:247-260` derives a syndrome using the private key and enters `BGF_decoder`. `decode_ml.c:305-348` branches on syndrome bits (`if (s[bit])` and `if (prev_s[bit])`), while the threshold/state computation and black/gray-flip updates are driven by that secret-derived syndrome. `kem.c:276-289` also branches on the decoded-error comparison to select either `sigma` or `m_prime` for the shared-secret hash. These are variable-control-flow candidates; the comparison branch is not itself proof of key recovery. The same path also has secret-indexed accesses and further secret-dependent branches: `convert2compact` (`conversions.c:11-30`, called at `kem.c:249-250`) branches on each private-key bit; `ntl_mod_mul` (`ntl.c:249-273`) branches on each bit of the sparse operand, which is `h0` in `compute_syndrome` (`kem.c:86`); the decoder indexes the syndrome by private support positions (`decode_ml.c:44-86`); and the re-derivation of `e` from `m_prime` (`kem.c:274`, `kem.c:32`) tests and sets bits at secret-derived positions in `generate_sparse_rep` (`sampling.c:57-85`). Key generation uses the same sampler for `h0` and `h1` (`kem.c:127-128`) and a data-dependent Euclidean loop for the inverse of `h0` (`ntl.c:206-247`, `kem.c:136`). No variable-divisor instruction was established in the representative trace.

Status: source-level CT concern; no controlled timing/cache measurement or complete extraction has been reproduced. The path should be hardened and retested before any constant-time claim.
