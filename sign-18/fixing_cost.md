Yes: the public-key-only forgery of sign-18-5 uses the public variable permutation and zone order that every verifier uses, so its repair is a change of construction with no costed proposal, in all four parameter sets.

Impact: not bounded
Scope: Construction (large), specification and code
Assessed: 2026-11-23

## Attacks considered

- sign-18-1: A fixed 512-bit message prehash caps forgery security at 256 bits (Design, Confirmed)
- sign-18-5: Public variable permutation permits signature forgery (Design, Confirmed)

## Remediation

- **sign-18-1.** Root cause: the message is first compressed to h_µ = H_msg(µ) of 64 bytes at every level (eq. 27–28, physical p. 17; `origami.h:27`, `SIG_AlgorithmInstance.c:51,80`), and only h_µ enters the salted target (eq. 29). The costed repair is the usual one for a narrow prehash: H_msg outputs twice the level, 96 bytes at Origami-384 and 128 bytes at Origami-512. The contest `pseudohash` that the code calls has 768- and 1024-bit forms (`auxfunc.c:281,353,460-472`). Scope: Function, specification and code. In the code the change is the constant `BYTES_DIGEST` and the adapter's absorb limit: `shake_absorb` stops at 208 bytes (`symmetric_iccs.c:9-11,42-51`), and the `sign-known` stream would grow from 186 to 218 bytes at Origami-384 and from 218 to 282 bytes at Origami-512, so the limit has to rise with the digest (the limit is the defect of sign-18-7, Low, not costed). Impact: none. h_µ is only hashed. It is not in the public key (param_id, seed_pk, R_pk) or in the signature (σ, salt), and the target space F_16^M has 3616 and 4640 bits and the salt 48 and 64 bytes, so no transmitted object grows. The message is absorbed by one hash call as before, and the target derivation and the signing streams absorb 32 or 64 more bytes each, against about 1.09×10^8 and 2.07×10^8 seed-derived coefficients per verification. The report records no proposed fix. Not checked: the contest hash is taken as an ideal replacement of the needed width; §2.4.1 names SHAKE256 as a possible instantiation, and whether its capacity carries a 384- or 512-bit level is outside this finding.
- **sign-18-5.** Root cause: the specification derives the variable permutation Π_pub from the public seed and defines P_pub = G ∘ Π_pub^-1 (§2.5.6, physical pp. 20–21), and the public key expansion gives every zone's affine coefficients, so anyone can undo the permutation and solve zone by zone as the signer does. This is a structural break of the trapdoor and not a property of one parameter set: the verifier itself undoes the permutation and evaluates the map zone by zone (`origami_ref.c:469-514`), and the report records the result that the submission's MT-MQ Assumption 7 fails in its independent-coefficient model for every submitted set. A repair has to hide the zone structure from the holder of the public key, which changes the public map, the compressed public-key format that is built on public zone positions (physical pp. 14–16), and the hardness assumption. Scope: Construction, specification and code. Impact: not bounded; the report records no proposed fix, so there are no figures to quote, and no repaired construction is specified from which sizes or work could be counted. Not checked: the forgery was not rerun, and ePrint 2026/2390 was not read.
