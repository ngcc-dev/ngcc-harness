## Remediation

- **sign-04-1.** The repair makes the code follow the specification: the encoder integer gets three 64-bit words where `WOTS_UINT_WORDS` is `SPX_N / 8 = 2`, and `chain_lengths` loads all 20 message bytes. The specification is sound on the point: it encodes Int of the whole n-byte message (Algorithm 6, line 5; Algorithm 7, line 5; physical pp. 23–24), and the specified `len` and `w` of both sets admit more than 2^160 constant-sum encodings, so no parameter changes. Scope: Function, code (`wots.c`, one constant and the load loop, in the four 160-bit trees). Impact: none (count for bytes and hash calls, judgment for the integer work). The signature stays `len` values of n bytes per layer. The hash counts are fixed by `len`, `w` and the constant sum: signing walks every chain to its end, and verification makes Σ(w_i − 1) − cs chain steps for any message. The code skipped no specified hashing. The encoder itself does more integer work, one more word in at most 12,155 (160f) or 12,978 (160s) compare-and-subtract steps per signature or verification, against 6,120 and 6,710 hash calls per verification; that is under 1% (judgment). The encoder's static table grows by half, to 332,592 bytes (160f) and 526,008 bytes (160s). The table is filled once per process, with 235,635 (160f) and 985,558 (160s) additions that each gain a word; this one-time work is not counted per operation. The report records no proposed fix. Not checked: nothing was built or run, and the optimized trees were checked only for the same lines.
- **sign-04-2.** The repair writes the whole chain index into the 4-byte `chainAddr` word where `set_chain_addr` stores one byte. The specification is sound on the point: the address words are 4 bytes and the FORC `chainAddr` ranges over 0 to k·2^a − 1, where k·2^a is between 3,584 (160f) and 385,024 (512s). Scope: Single line, code (`address.c:81`, in the sixteen trees). Impact: none (count). The 32-byte address is already hashed whole, so no hash input grows; each FORC leaf still costs one PRF call and `w'` chain hashes; nothing in the address is transmitted. The finding is Probable and is costed as reported; the answer does not rest on it alone. The report records no proposed fix. Not checked: nothing was built or run; other differences between the specified and the implemented hash inputs are outside the two findings and are not costed.
