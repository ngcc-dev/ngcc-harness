## Attacks considered

- sign-30-1: The normal build deterministically exposes every signing key (Implementation, Confirmed)
- sign-30-2: The specified 128-bit round seeds permit collision-accumulation forgeries (Design, Confirmed)
- sign-30-3: SHAKE256 capacity limits TRINE-512 transcript collision security (Implementation, Confirmed)
- sign-30-4: TRINE-512's invariant-attack estimate falls about 5.5 bits below target (Design, Lead)

## Remediation

- **sign-30-1.** The normal build never seeds its AES-CTR generator: `randombytes.c:160` defines `randombytes_init`, `randombytes.h` does not export it, and key generation draws the secret seed at `trine.c:209`. The costed repair seeds the generator from the operating system before first use. Scope: Single line, code. The specification samples the key at random (Algorithm 5, physical p. 12) and stays as it is. Impact: none.
- **sign-30-2.** The root cause is the unsalted 128-bit round seed of the specification (§3.4, p. 13). The submitted code already contains the repair: a 2λ-bit salt is drawn per signature (`trine.c:352`), absorbed with the round index when each round seed is expanded (`trine.c:44–69`), and appended to the signature (`params.h:174,188`). The report records the submitted code as not affected. The repair is therefore a specification change: Algorithms 6 and 7 and the size formula of §3.5 gain the salt. Scope: Function, specification. The signature encoding changes, because the salt is appended. Impact: the stated sizes do not include the salt, so the signature grows by 32 bytes at TRINE-128, which is +1.0% for Balanced and +2.0% for ShortSig (count). If the salt is specified for all sets as the code has it, the 256- and 512-bit signatures grow by 64 and 128 bytes, +0.3% to +1.1%. No work is added to the code that was timed. A key-use limit is not a repair, because the attack fits within 2^64 − 1 signatures. Widening the round seeds to 256 bits instead would add 16 bytes per base round, 1,376 bytes for Balanced (+44%) and 400 bytes for ShortSig (+25%).
- **sign-30-3.** The normal build hashes the transcript with SHAKE256 at every level (`hashkdf.c:262–313`), which has a 512-bit capacity. The costed repair gives the TRINE-512 transcript hash a 1024-bit capacity. With the same Keccak permutation the rate falls from 136 to 72 bytes (`fips202.h:8,10`). Scope: Sub-algorithm, specification and code. The specification asks only for a hash with 2λ output bits (Algorithm 6, p. 13) and names none, so it has to state the capacity or name the hash, and the code changes the sponge of the 512-bit sets. Impact on sizes: none, the digest is already 2λ bits. Impact on work: the transcript absorbs r encoded forms of 797,162 bytes, so its permutation calls grow by a factor 136/72 = 1.89. That is 2.78 million more calls for Balanced and 1.21 million more for ShortSig, per signature and per verification. Each round also samples a corank-one point by trial, about q·n^3 field operations by the specification's own count (p. 19), and that dominates. At a generous 2,000 cycles per permutation the added calls are 0.3% of the stated signing cycles and 0.4% and 0.6% of the stated verification cycles. Impact: none. Not costed: the round XOF and the key expansion also use SHAKE256 (`hashkdf.c:93–253`); the finding does not name them.
- **sign-30-4.** This is a Lead and does not decide the answer. Under the finding's own formula the smallest change that reaches 512 bits is n = 82 with q, r, K and X unchanged: 512.6 bits, against 506.5 at n = 81. Scope: Parameter set, specification and code. Impact at TRINE-512: public key +3.8%; signature +0.7% for Balanced and +0.9% for ShortSig; point sampling, about q·n^3 per round, +3.8%; canonical forms and the key-generation pullback, about n^4, +5.0% (estimate). This is a zero-margin lower bound, and key generation sits at the 5% mark, so the "No" with leads is a judgment. One more step, n = 83, would give +7.6% on the public key and +10.2% on the n^4 work. The alternative of a larger field at n = 81 needs a 13-bit prime (4507 is the smallest prime that reaches 512 bits), which costs +8.3% on the public key and about +10% on point sampling. Not checked: the rare-triangle and hull estimates at n = 82.
