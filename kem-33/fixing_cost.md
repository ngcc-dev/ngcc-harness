## Attacks considered

- kem-33-3: The optimized API generates predictable keys and encapsulations (Implementation, Confirmed)
- kem-33-4: The optimized FO check compares word counts as byte counts (Implementation, Confirmed)
- kem-33-5: Same-key multi-instance decoding puts four QUBE sets below target (Design, Confirmed)
- kem-33-6: Optimized QUBE-384 and -512 expand keys and encryption randomness from 256-bit seeds (Implementation, Confirmed)

## Remediation

- **kem-33-3.** Root cause: the optimized `crypto_kem_keypair` and `crypto_kem_enc` draw their seeds, message and salt from a file-scope SHAKE-256 context that no API path seeds. The costed repair draws them from the ICCS generator `drng_algorithm`, as the reference tree does, or seeds the context from it once. Scope: Single line, code. The specification takes this randomness as an input (Figs. 4 and 5, physical p. 9) and stays as it is. Impact: none. The code skips no specified work: the same bytes are drawn, 2·`SEED_BYTES` + λ/8 in key generation and λ/8 + 16 in encapsulation. The report records no proposed fix.
- **kem-33-4.** Root cause: `vect_compare` takes a byte count, and `crypto_kem_dec` passes it counts of 64-bit words for u and v. The costed repair passes the byte lengths `VEC_N_SIZE_BYTES` and `VEC_N1N2_SIZE_BYTES`, which the same routine already uses to build the rejection-key input, so that the check is c′ = c of Fig. 6, step 6 (physical p. 10). Scope: Single line, code. Impact: none. The corrected code does work that the submitted code skips: 2,811 more byte comparisons at QUBE-128, 9,059 at QUBE-256, 18,217 at QUBE-384 and 30,582 at QUBE-512, each one XOR and one OR. The same call hashes the public key and the whole ciphertext, more than twice as many bytes (6,645 at QUBE-128), and runs five ring multiplications. Table 11 reports 338,000 to 5,720,000 cycles for it, and the added comparisons stay under 1% of those figures even at one cycle per byte (0.83% at QUBE-128). The report records no proposed fix.
- **kem-33-5.** Root cause: every ciphertext under one key gives r rotated targets u = h1·f1 + h2·f2 + g for one [3r, 2r] decoding search, and the estimate falls below target only after 2^71 or more honest ciphertexts. The costed repair is a stated limit of 2^64 encapsulations per public key. At that limit the finding's estimator gives 2^130.999 (QUBE-128), 2^194.657 (QUBE-192), 2^259.710 (QUBE-256), 2^390.991 (QUBE-384) and 2^519.509 (QUBE-512), all at or above target. Static keys, which the specification names as a use (physical p. 3), and the security notion are kept. Scope: Single line, specification. Impact: none. The report records no proposed fix. Alternative without a limit: at 2^80 ciphertexts the estimates are 2^126.041, 2^188.105, 2^252.971 and 2^383.527, and QUBE-512 stays above target. At unchanged r the smallest total weights 2wf + wg that reach the targets are 87 (from 85), 128 (from 125), 168 (from 166) and 249 (from 248). A heavier error raises the decryption failure rate. If r grows in proportion to the error products 2·wx·wf + wy·wg + we of §2.3, the public key grows about 2.3%, 2.4%, 1.2% and 0.4% and the ciphertext about half as much (judgment). Table 7 (physical p. 16) states failure levels of 137.5, 200.1, 264.3 and 392.4 bits for these sets, so part of the heavier error may fit at unchanged r. The failure rate of Propositions 2 to 5 was not recomputed, and work was not counted for the alternative. These values are costing aids, not proposed parameters.
- **kem-33-6.** Root cause: every optimized parameter file fixes `SEED_BYTES` at 32, where the specification gives ρ, ρ0, ρ1 and ρc λ/8 bytes (Figs. 1 and 2, physical pp. 7–8). The costed repair sets `SEED_BYTES` to λ/8 in the 384- and 512-bit parameter files and widens the output of `hash_i`, a SHA3-512 call with a fixed 64-byte output, to 2·`SEED_BYTES`. The reference tree does both. At QUBE-384 the call that derives K and θ then asks `pseudohash` for (64 + 48)·8 = 896 bits, a length it does not accept, so that length changes as well. Scope: Function, code. Impact: none against the stated sizes. The optimized public key holds a 32-byte ρ0 and is 20,722 and 33,996 bytes at QUBE-384 and QUBE-512; with a λ/8-byte ρ0 it is 20,738 and 34,028 bytes, the values that Table 5 states. The ciphertext holds no seed. The message m is already λ/8 bytes at both levels, so the plaintext does not widen. Work: each XOF call absorbs 16 or 32 more seed bytes in its first block, the PRG output grows by 32 or 64 bytes and the output of G by 16 or 32, against two to five ring multiplications per operation; under 1%. Not costed: the XOF itself. Table 3 (physical p. 11) marks SHAKE-256 as a placeholder at these two levels, and a wider XOF is outside this finding. The report records no proposed fix.
