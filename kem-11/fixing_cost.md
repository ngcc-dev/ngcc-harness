## Attacks considered

- kem-11-1: COMPASS-KEM-384 and -512 use a 256-bit key-generation root (Implementation, Confirmed)

## Remediation

- **kem-11-1.** Root cause: the code fixes `COMPASS_KEM_SYMBYTES` and `COMPASS_KEM_SSBYTES` at 32 for every level (`params.h:86–87`), while the specification gives the seed ι, the message m, the coins r, the rejection value z and the key K n/8 bytes each (Algorithms 1, 4, 5 and 6, physical pp. 13–16), which is 64 bytes at n = 512. The costed repair makes the code follow those algorithms for the secret values: 64-byte ι, σ, m, r, z and K, with G returning two 64-byte halves. It is the cheapest credible repair because it is the specification's own text and it leaves the public seed ρ at the 32 bytes that Table 2 already assumes. The wider message needs no new ciphertext room: m is encoded one bit per coefficient of c2 (Algorithm 2 step 7, physical p. 14) and c2 has n = 512 coefficients, of which the code fills 256 and zeroes the rest (`poly.c:338–351`). Scope: Function, specification and code. In the code: the two constants, the output length of `hash_g` (`symmetric.h:42–43`), and a separate length for ρ, which now shares the constant. In the specification: the "32-byte core seed" note (physical p. 25) and the lengths of ρ, H(ek) and z, which the text gives as n/8 bytes (physical pp. 10, 15) and Table 2 counts as 32. Impact: none. Public key and ciphertext are unchanged. The secret key grows by the 32 added bytes of z, to 4,736 and 6,272 bytes (under 1%). The hash and XOF calls are the same in number, the calls that take a secret seed absorb 32 more bytes each, and G returns 64 more bytes. The specification names matrix expansion as the most compute-intensive step (physical p. 26), and it is unchanged. Alternative: if ρ also follows the n-bit text, the public key grows by 32 bytes, +1.5% at COMPASS-KEM-384 and +1.1% at COMPASS-KEM-512. Failure probability: the model of §3.3 matches Table 3 best with the union bound over all n coefficients, which indicates that the stated bound already covers an n-bit message. The match is within 0.5 bits, and Table 3's exact method was not recovered. If the table counts 256 coefficients instead, the rate with an n-bit message is one bit above the stated one, 2^−403.51 and 2^−249.31. Not counted: the hash and XOF are the contest's `pseudohash` and `pseudoXOF`, which the ruleset costs as ideal replacements by calls and bytes. In the helper as built, a 64-byte sampler seed takes two SM3 compressions per 32-byte output block where the submitted one takes one, about 1.5% more compressions in key generation and encapsulation. Decapsulation as built also hashes the ciphertext twice for a 64-byte rejection key, about 3% more compressions in all. H keeps its 256-bit output: the finding does not concern it, and its width was not assessed.
