## Attacks considered

- hash-24-2: Truncated tree chaining values cap QSH second-preimage security (Design, Confirmed)

## Remediation

- **hash-24-2.** The root cause is that a leaf chunk passes on a chaining value of m/2 = n bits and no compression call binds the position of the chunk, so one replacement chunk is tested against all T leaf chaining values of a long target at a cost of 2^n/T. The costed repair is the standard chunk counter of tree hashing: the chunk index t becomes an input of the leaf compressions, which ties a replacement chunk to the one chaining value at its own position. `pseudocode.md` notes that QSH, unlike BLAKE3, which the specification cites as its tree-hash comparison ([44], physical p. 22), mixes no chunk counter into the leaf compressions. F_{3,w} already has an input for it. The w-bit flag word is XORed into state word S_0 (Algorithm 3, line 5), and the message block of the same call does not enter that word before the permutation (line 3 adds it to words v to u − 1). Every chunk starts from the fixed H^(0), so an index XORed there gives each leaf a different first permutation input. At QSH-1024 the chunk indices, up to 2^49, fit in the 64-bit flag word beside the four flag bits. At QSH-512 the indices, up to 2^50, do not fit in a 32-bit word, and the index needs a second state word. Scope: Function, specification and code: the flag computation of Algorithm 4, the flag input of Algorithm 3 at w = 32, and the matching lines of the chunk loops. Parent calls are not changed in this costing; their inputs are leaf values that the index ties to positions. Impact: none. No compression call is added, the tree shape is the same, and every block still carries m message bits. The answer does not depend on the flag word: an index that took 64 bits of message space in the first block of each chunk would cost 64/16384 = 0.4% at QSH-512 and 64/32768 = 0.2% at QSH-1024, which is still none. The other standard repair, a chaining value wider than m/2 bits, costs more: a parent could no longer take both children in one m-bit block, and with two calls per parent a full chunk takes 18 compression calls instead of 17, counting its 16 blocks and one parent per chunk (Algorithms 4 and 5), +5.9%. QSH-768 is not affected and does not change. The report records no proposed fix for this finding. Not checked: whether an index in the flag word interacts with the invariant subspace of hash-24-1; the optimized 64-bit path and the NEON code. Nothing was implemented or measured.
