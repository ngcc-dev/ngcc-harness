## Remediation

- **kem-34-5.** The root cause is the hardness of the Rudraksh2-512-I MLWE instance (ℓn = 2048, q = 7681, η = 2): the finding's dual-hybrid estimate is 2^495.5 against a target of 2^512. The repair is a new parameter set, searched with the finding's estimator and conventions. Within rank 8 no admissible set was found. The instance gets harder only with more noise, and the submitted failure probability of 2^-160.5 sits at the specification's 2^-160 bound for this level: η = 3 reaches 2^519.9 but takes the failure probability to about 2^-71. A larger modulus makes room for noise, but 7681 is the smallest prime that supports the specified NTT at n = 256, and for each of the five 14-bit primes that do, every η inside the failure bound leaves the estimate below 2^503. The degree cannot drop below 256, because the message has 2n bits, so the dimension ℓn grows in steps of 256. The costed repair is therefore one rank step, ℓ = 9 with q = 7681 and η = 1, values that are a costing aid and not a recommended set: dual hybrid 2^517.1 (2^516.1 on a wider search), primal BDD 2^565.1, and a failure probability far inside the bound (model 2^-578). With η = 2 at rank 9 the model failure probability is 2^-145 to 2^-151, outside the bound; the public key is the same either way. Scope: Parameter set, specification and code: Tables 1, 2 and 14 and the failure analysis, and in the code `KEM_L`, `KEM_ETA` and the η = 1 sampler, which the 512 tree lacks and the 256 tree has. Impact: the public key holds ℓ uncompressed polynomials and grows from 3392 to 3808 bytes, +12.3%; the secret key grows from 6848 to 7680 bytes. The ciphertext grows from 3552 to 3968 bytes (+11.7%) with the submitted compression moduli, and is 3680 (+3.6%) or 3392 bytes (no increase) if p is lowered to 2^12 or 2^11, where the model failure probability is 2^-395 or 2^-249. The public matrix has ℓ^2 entries, 81 for 64, and its sampling is 99% of the XOF output of the submitted code, so the XOF output of each operation grows by 26%; forward transforms grow by 12.5% and pointwise products by 25% to 27%. Alternative: the specification's own Rudraksh2-512-II parameters (ℓ = 9, q = 4001, η = 1) give a public key of 3520 bytes (+3.8%) and a ciphertext of 3712 bytes (+4.5%) and reach 2^547.0 on the wider search. They are rank 9 too (at rank 8 that modulus gives 2^484.0), so by the same call pattern the XOF output grows by 16%. No implementation of that set was submitted, and its modulus does not support the specified NTT (kem-34-4), so its multiplication cost is not counted. No consistent choice keeps every metric under 10%. The report records no proposed fix. The estimate is a lower bound: it has no margin, it covers the public-key instance as the finding does, and it rests on the estimator's dual-attack heuristics. The failure figures come from a Gaussian model that reproduces the submission's six recorded values to within about 3 bits; the submission's own failure-rate program was not run. Core-SVP figures and 15-bit moduli (15% larger coefficients by themselves) were not evaluated. Sets with a smaller CBD parameter for the encryption noise than for the key are not a shape that Table 1 has and were not costed; one estimate of the ciphertext instance of such a shape (ℓ = 8, q = 12289, secret η = 4, error η = 1) gave 2^465.7.
