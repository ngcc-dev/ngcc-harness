## Attacks considered

- sign-08-1: The implemented message representative caps forgery security at 256 bits (Implementation, Confirmed)
- sign-08-2: The compression-consistency restart leaks an equivalent DARTS-128 signing key (Design, Confirmed)
- sign-08-4: AVX2 DARTS-512 samples its signing secret from 256 seed bits (Implementation, Confirmed)

## Remediation

- **sign-08-1.** Root cause: DARTS-512 signs the unsalted digest µ = H1(pk, M), the code emits 64 bytes of it at every level, and the specification gives H1 no output length. The costed repair states H1's output as 2λ bits and gives µ 128 bytes at DARTS-512. It is the usual repair of a narrow message representative, and it is cheaper than a salt, which would have to be sent. A longer squeeze alone does not do this in the submitted code: its XOF wrapper first hashes the whole input into a 64-byte `derived_seed` with the contest's 512-bit hash and expands that, so a µ of any length would keep the 2^256 collision cost. µ has to come from a 1,024-bit digest of pk ‖ M, which the contest's `pseudohash` offers. Scope: Function, specification and code: one statement of H1's output length in the specification, and in the code the µ computation of signing and verification with its buffers. `CRHBYTES` also sizes the secret seed and the mask seed, so µ gets its own constant or all three widen; none of them is transmitted. Impact: none. µ is absorbed by H1(K, µ) and by H2 and is not part of σ = (c, e_z, x, Encode(h)). By calls and bytes, signing and verification make the same one hash call over pk ‖ M with a digest 64 bytes longer, and each challenge hash absorbs 2,688 bytes in place of 2,624. The report records no proposed fix for this finding. The contest hash is counted as an ideal one with the needed output length. Not costed: the additional FIPS 202 build, which the finding does not list as affected, takes µ from SHAKE256, and its 512-bit capacity keeps the collision cost near 2^256 at any output length; a wider µ there needs a sponge of 1,024-bit capacity, whose rate is 72 bytes against 136.
- **sign-08-2.** Root cause: Step 9 of Algorithm 7 tests Comp_d(ω) = Comp_d(ω + (1 − b)cα), which always holds for b = 1, so the restart depends on the hidden bit and tilts the published (c, z). The costed repair is the submitters' proposal, as recorded in the report and not evaluated: compare with Comp_d(ω + (1 − 2b)cα). It is one comparison, Algorithm 7 line 9, and in the code the term built at `sign.c:187–188` for the test at `sign.c:193–199`; the hint at `sign.c:253–261` is not part of the proposal. The Mcomp formula of Section 1.4 and the Mcomp and M rows of Table 2 follow from it. Scope: Single line, specification and code. Impact: no size changes. The test now fails for both values of b with the probability that Section 1.4 gives for b = 0, so Mcomp goes from 1.12 to 1.27 at DARTS-128, 1.12 to 1.26 at DARTS-256 and 1.22 to 1.57 at DARTS-512, and the expected number of expandY calls per signature M rises by 13%, 13% and 29% (count). Every call repeats the hyperball sampling, the product A⌊y⌉ and the challenge hash before the test (`sign.c:167–199`). The specification attributes over 60% of signing time to hyperball sampling alone, so signing time rises by 8% to 13% at DARTS-128 and DARTS-256 and by 17% to 29% at DARTS-512 (estimate). Key generation and verification do not change. The figures keep the submitted parameters, as the proposal does. Not checked: version 2.0 of the specification and code; whether the corrected test changes how often the rANS encoding overflows its fixed reserve and restarts; the 60% share, which the specification states for its FIPS 202 build; whether a smaller compression parameter d, which lowers this restart probability and enlarges the verification radius B′′, could be chosen.
- **sign-08-4.** Root cause: the AVX2 wrapper `stream256_init` absorbs 32 seed bytes, where Table 2 gives DARTS-512 a 64-byte seed and the reference sampler absorbs all 64. The costed repair passes the full seed length in that wrapper. The specification is sound on this point and stays as it is. Scope: Single line, code. Impact: none. No object changes, and each sampler stream absorbs 32 more bytes. The same wrapper also feeds the AVX2 hyperball sampler, whose mask streams then absorb the full seed as well; the repair adds no other work. The NEON tree passes the full length already. The report records no proposed fix for this finding.
